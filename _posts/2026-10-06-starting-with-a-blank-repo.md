Every project starts with an empty directory.

There's something I like about that moment — before the first commit, before the first decision calcifies into a constraint. The possible space is maximally open. You can still be exactly as deliberate as you want.

This blog is that blank repo. I've been meaning to have a place to write for a while. Not a portfolio, not a resume — just somewhere to think out loud and leave a record of the things I figure out.

What I expect to write about:

- **Software** — systems design, engineering trade-offs, things I've built and what I learned building them
- **Research** — notes and reactions to papers and ideas worth engaging with
- **Reads** — thoughts on books, essays, longform pieces
- **Craft** — the practice of building software deliberately, the habits and approaches that make the difference between code that works and code that lasts

The common thread is problem solving: understanding a system well enough to see what's actually wrong, then fixing it carefully.

I'll write when I have something worth saying. The goal is specificity over frequency.
